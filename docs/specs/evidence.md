# Evidence
Paths: crates/rastro-core/, crates/rastro-storage-sqlite/, crates/rastro-cli/, crates/rastro-plugin-sdk/, crates/rastro-test-connector/, crates/rastro-connector-github/

## Requirements
- **R1** WHEN the owner runs `rastro source add project --connector github --repo o/p --scope personal`, THEN `rastro source list` shows `project` with its connector, selector, scope, freshness rule and window start, and the config file holds it. (from cited-search-github/S1)
- **R2** WHEN a source is registered but has never synced, THEN `rastro coverage project` reports "never looked". (from cited-search-github/S2)
- **R3** WHEN `RASTRO_HOME` is set, THEN data and config live under it. Otherwise `XDG_DATA_HOME` and `XDG_CONFIG_HOME` are used, and failing those, `~/.local/share/rastro` and `~/.config/rastro`. (from cited-search-github/S3)
- **R4** WHEN anything tries to update or delete stored evidence, THEN the store rejects it and the evidence is unchanged. (from cited-search-github/S3a)
- **R5** WHEN migrations written on different branches are merged in any order, THEN each applies exactly once, in timestamp order, on new and existing databases, and a database with an unknown newer migration is refused. (from cited-search-github/S3b)
- **R6** WHEN `rastro sync project` runs a connector that submits evidence and a complete coverage report, THEN the evidence is stored, coverage records "found" for the window, and the run log shows `ok` with the plugin version and the core's counts. (from cited-search-github/S4)
- **R7** WHEN a complete sync submits no evidence, THEN coverage records "empty" for the window. (from cited-search-github/S4a)
- **R8** WHEN a connector submits evidence without a location, span, quote or trust class, or whose quote's UTF-8 byte length differs from `end - start`, THEN the core rejects it and counts it as rejected. (from cited-search-github/S5)
- **R9** WHEN a connector submits a kind its grant doesn't permit, or sets a source or scope other than the bound one, THEN the core rejects it and counts it as rejected. (from cited-search-github/S6)
- **R10** WHEN a source's scope is outside the scopes its connector's manifest declares, THEN sync refuses to run it and records "couldn't look"; and WHEN a connector's coverage report or evidence names a window other than the bound one, THEN the core rejects it. (from cited-search-github/S6a)
- **R11** WHEN a connector runs, THEN it sees only the allowed environment variables and those its manifest declares, never the owner's other secrets. (from cited-search-github/S6b)
- **R12** WHEN connector-supplied text reaches the terminal (rejection reasons, search results), THEN control characters are escaped. (from cited-search-github/S6c)
- **R13** WHEN the connector answers `initialize` with an unsupported major version or a different manifest id, THEN the run fails with `protocol` before any evidence is ingested. (from cited-search-github/S7)
- **R14** WHEN a manifest omits `permissions.env`, THEN it is treated as an empty list and the plugin still loads. (from cited-search-github/S7a)
- **R15** WHEN the connector exits before `run.finish`, THEN the run fails with `interrupted`, coverage records "couldn't look", the evidence already accepted stays, and `rastro sync` exits non-zero. (from cited-search-github/S8)
- **R16** WHEN the connector sends a malformed or oversized line, or is silent past the timeout, THEN the core kills it, the run fails with `protocol` or `timeout`, and no partial message is ingested. (from cited-search-github/S9)
- **R17** WHEN a connector writes to stderr, THEN the core relays each line with control characters escaped and length bounded, without ever blocking the connector. (from cited-search-github/S9a)
- **R18** WHEN a connector writes to stdout faster than the core reads, THEN the core holds a bounded number of lines in memory and the connector waits (backpressure); the run still completes. (from cited-search-github/S9b)
- **R19** WHEN a connector stops reading its stdin, THEN the core's write gives up at its deadline, kills the connector, and the run fails with `timeout`. (from cited-search-github/S9c)
- **R20** WHEN a connector sends `run.finish` but doesn't exit, or a child of it keeps its pipes open, THEN the core kills it after a shutdown deadline, keeps the finished run, and releases the sync lock. (from cited-search-github/S9d)
- **R21** WHEN a connector writes more stderr than the relay's bound, or the core's own stderr blocks, THEN the relay drops the excess and says how many lines it dropped, and neither the connector nor the run waits on it. (from cited-search-github/S9e)
- **R22** WHEN a connector sends invalid UTF-8, or a message that isn't a JSON-RPC 2.0 envelope (wrong `jsonrpc`, missing `method` or `id` where required), THEN the run fails with `protocol` and nothing from that line is ingested. (from cited-search-github/S9f)
- **R23** WHEN a connector causes many core diagnostics (rejected submissions or coverage reports) and the core's stderr isn't drained, THEN they go through the same bounded, lossy relay and the run never waits on them. (from cited-search-github/S9g)
- **R24** WHEN the core's reply to `run.finish` can't be written before its deadline, THEN the run fails with `timeout`. (from cited-search-github/S9h)
- **R25** WHEN a message has an `id` JSON-RPC doesn't allow (object, array, boolean), or mixes `method` with `result` or `error`, THEN the run fails with `protocol` and nothing from that line is ingested. (from cited-search-github/S9i)
- **R26** WHEN a connector, or a child of it, still holds its pipes when the run ends, THEN the host kills the connector's process group and releases its reader threads and pipe descriptors within the shutdown deadline. (from cited-search-github/S9j)
- **R27** WHEN the connector has exited, THEN the host signals its process group before reaping it, so the signal can never reach a process that reused its id. (from cited-search-github/S9k)
- **R28** WHEN storage rejects a submission (including span offsets the store can't represent, which are refused before storage) while the core's stderr is blocked, THEN the diagnostic goes through the bounded relay and the run doesn't wait on it. (from cited-search-github/S9l)
- **R29** WHEN one host process runs many syncs while its stderr is blocked, THEN the threads and queued output for printing stay bounded across runs, not per run. (from cited-search-github/S9m)
- **R30** WHEN the core starts and finds a run that never finished, THEN it marks that run `interrupted`. (from cited-search-github/S10)
- **R31** WHEN the core recovers a run that never finished, THEN coverage records "couldn't look: interrupted" for that run's source, scope and window, which are stored when the run starts. (from cited-search-github/S10a)
- **R32** WHEN the connector reports "couldn't look" with a typed reason (e.g. `rate_limited`, with a retry time), THEN coverage stores the reason and the window is never reported as empty or complete. (from cited-search-github/S11)
- **R33** WHEN a connector sends `run.finish` without a coverage report the core accepted (none sent, or every one rejected), THEN the run fails with `protocol` and coverage records "couldn't look: protocol". (from cited-search-github/S11a)
- **R34** WHEN syncing a fixture repo, THEN exactly the issues and PRs the owner authored, is assigned to, was asked to review, or is @mentioned in become evidence, together with their comments. Items with none of those don't. (from cited-search-github/S12)
- **R35** WHEN an item in the window has comments updated before or after the window, THEN only the comments updated within `[from, to)` become evidence. (from cited-search-github/S12a)
- **R36** WHEN syncing, THEN the search queries the fixture server receives name the bound repo and window. (from cited-search-github/S12b)
- **R37** WHEN GitHub evidence is recorded, THEN each title, body and comment is its own observation with its URL, field path, byte span, quote, capture time and source update time. Prose is `untrusted content`; API fields are `structured`. (from cited-search-github/S13)
- **R38** WHEN labels or assignees are recorded, THEN each observation quotes the actual value at its own field path (`/labels/N/name`, `/assignees/N/login`), never a list the connector assembled. (from cited-search-github/S13a)
- **R39** WHEN prose contains multi-byte Unicode, THEN each span is in UTF-8 bytes and the quote equals the bytes at that span. (from cited-search-github/S13b)
- **R40** WHEN results span several pages and a mid-run response is a rate limit, THEN the evidence from completed pages is kept and coverage records "couldn't look: rate_limited", not "found". (from cited-search-github/S14)
- **R41** WHEN a search reports more than 1000 results or `incomplete_results`, THEN coverage records "couldn't look: result_cap", never "found". (from cited-search-github/S14a)
- **R42** WHEN GitHub answers 403 with `x-ratelimit-remaining: 0` or a secondary-limit signal (`retry-after`), THEN coverage records `rate_limited` with its retry time; any other 403 records `forbidden`. (from cited-search-github/S14b)
- **R43** WHEN an item's comments span several pages, THEN every page is read. (from cited-search-github/S14c)
- **R44** WHEN GitHub content contains instruction-like or command-like text, THEN the connector's requests are still only the fixed GET endpoints. The fixture server records every method and path. (from cited-search-github/S15)
- **R45** WHEN a `Link` header or a redirect points away from the API host, THEN the connector doesn't follow it, never sends the token there, and coverage records "couldn't look: protocol". (from cited-search-github/S15a)
- **R46** WHEN the GitHub token is missing or rejected, THEN coverage records "couldn't look: auth" and no token appears in evidence, the run log or protocol messages. (from cited-search-github/S16)
- **R47** WHEN a source is synced again and nothing changed, THEN no new evidence is written, the run is linked to the existing evidence, and the unchanged count says so. (from cited-search-github/S17)
- **R48** WHEN a body changes A→B→A across three syncs, THEN there are three observations; `search` shows only the latest, and `search --history` shows all three. (from cited-search-github/S18)
- **R49** WHEN `rastro search "x"` matches, THEN each result shows the quote, the link, the span, the capture time, the trust class, the scope, and the source's coverage and freshness. (from cited-search-github/S19)
- **R50** WHEN a search matches nothing, THEN the output says so and states the coverage of each source searched. (from cited-search-github/S20)
- **R51** WHEN a source's last complete check is older than its freshness rule, or its latest attempt failed, THEN `rastro coverage` answers "unknown", and still shows the last successful check and the failure reason. (from cited-search-github/S21)
- **R52** WHEN the full-text index is dropped and `rastro index rebuild` runs, THEN the same search returns the same results with their citations intact. (from cited-search-github/S22)
- **R53** WHEN the index is rebuilt, THEN it behaves like a freshly migrated one: the same stemming and diacritics matches, and the same latest and history results. (from cited-search-github/S22a)
- **R54** WHEN any command runs with `--json`, THEN its output validates against the versioned operation schema. (from cited-search-github/S23)
- **R55** WHEN a known command runs with `--json` but its arguments don't parse, THEN it prints a schema-valid error result for that operation and exits non-zero; `--help` and `--version` still work. (from cited-search-github/S23a)
- **R56** WHEN a command gets an argument that isn't valid UTF-8, THEN it never panics: for a known operation under `--json` it prints that operation's schema-valid error result, and either way it exits 2. (from cited-search-github/S23b)
- **R57** WHEN the owner registers one of their real repos and syncs, THEN searching for a phrase they remember returns it with a working link, and `rastro coverage` is accurate. (from cited-search-github/S24)
